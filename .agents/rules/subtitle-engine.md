# Subtitle Engine & Security Rules

This codebase deals with arbitrary user-uploaded media files, subtitle files (ASS/SSA, SRT, VTT, TXT), and Matroska (MKV) binary streams. Safety, bounds checking, and XSS sanitization are paramount.

---

## 1. Input Validation & DoS Guards

- **File Upload Limits:**
    - Plaintext subtitle files (`.ass`, `.ssa`, `.srt`, `.vtt`, `.txt`): Max **25 MB**.
    - Matroska container files (`.mkv`): Max **2 GB**.
    - Clipboard paste text: Max **10 MB**.
- **Diff Computation Bounds:**
    - Myers diff algorithm has $O(N \cdot M)$ worst-case complexity.
    - Always enforce `MAX_DIFF_LINES = 20_000` in `src/lib/engine/diff-engine.ts`.
    - Slice input lines exceeding the cap and set `isTruncated = true` with a user warning banner.

## 2. MKV / EBML Parsing Safety

- In `src/lib/engine/mkv-parser.ts`:
    - Verify EBML variable-length integers against `Number.MAX_SAFE_INTEGER`.
    - Clamp track header data reads to **10 MB**.
    - Clamp block group data reads to **5 MB**.
    - Guard cluster scan loops against infinite iterations when encountering negative or malformed element sizes (`cElemSize = -1`).
    - Sanitize track names and language codes using `sanitizeLanguageCode()` and `sanitizeTrackTitle()` in `language-names.ts`.

## 3. Subtitle Text Processing & Normalization

- In `src/lib/engine/text-processor.ts`:
    - **Alpha Timing:** When merging progressive reveal dialogues (`mergeAlphaTiming`), ensure line index 0 is never dropped when `lines.length === 0`.
    - **Drawing Commands:** Strip vector drawing blocks (`{\p1}...{\p0}`) using linear, bounded non-backtracking regular expressions to eliminate ReDoS.
    - **Style Exclusion:** Handle inline style resets (`\rStyleName`) and bracketed override tags cleanly so excluded styles are reliably dropped.
    - **Normalizers:** Normalize whitespace, smart quotes, and Japanese/anime honorifics idempotently.

## 4. Output Sanitization & XSS Prevention

- All diff HTML generated via `diff2htmlHtml()` must pass through `sanitizeDiffHtml()` before being rendered with `{@html ...}`.
- Sanitizer configuration must permit only safe elements (`table`, `tr`, `td`, `div`, `span`, `del`, `ins`, `svg`, `path`, etc.) and strip event handlers or scripts.
- Filenames and track titles inserted into patch headers must pass through `sanitizePatchHeader()` to prevent patch manipulation.
- Standalone HTML reports generated by `Toolbar.svelte` must embed a strict Content Security Policy (`default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:;`).
